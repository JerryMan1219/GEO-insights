# Chapter 4: GEO 内容优化工程

## Core Idea
GEO 的本质是以语义优化为核心的系统性内容工程——通过内容搭建、结构化、分发三层动作，让品牌在 AI 答案中获得 "被看见" 直至 "优先被看见" 的位置。

## Frameworks Introduced
- **GEO 内容四工程**：
  1. **信息纠偏**——保障真实性、全面性、时效性（旧内容更新、负面信息澄清、Sitemap 提交）
  2. **结构化表达**——标题内容分级、FAQ 格式、JSON-LD / schema.org 标记
  3. **打通抓取路径**——JS 渲染、语义锚点词库、Robots 解禁
  4. **语义增强**——"被看见" → "优先被看见"，强化用户意图词 + 权威域名 + 平台偏好适配

  - When to use: 任何 GEO 内容优化项目的工程路线图
  - How: 四个工程并行——纠偏内容、标记结构、打通路径、增强语义
- **内容搭建三维度**：
  - **用户身份解读**：让 AI 知道你的目标用户是谁
  - **用户使用场景**：在什么情境下使用
  - **AI 搜索意图**：用户会怎么向 AI 提问
  - When to use: 撰写 GEO 优化内容前
  - How: 列出 "用户身份×场景×意图" 三维矩阵，每条内容都击中至少一个交叉点
- **三层信源分发模型**：
  - **权威层**：政府/学术/主流媒体/官方文档/企业官网
  - **讨论层**：社交媒体/论坛/垂类媒体
  - **平台层**：根据不同 AI 平台的引用偏好针对性布局
  - When to use: 设计内容分发策略
  - How: 权威层打底、讨论层引爆、平台层补漏
- **AI 平台引用偏好**（关键差异）：
  - 豆包：侧重抖音、火山引擎等字节生态
  - 文心一言：侧重百度百科、百度知道、百家号
  - 千问：阿里生态（淘宝/支付宝/钉钉等）
  - 腾讯元宝：微信生态（公众号/视频号/小程序等）
  - Kimi：长文本/学术偏好
  - DeepSeek：技术圈/开发者生态
  - ChatGPT：英文世界 + 全球开发者社区
  - When to use: 选择目标平台 + 设计内容分发矩阵
  - How: 用 GEO 服务商追踪各平台引用信源分布，动态调整

## Key Concepts
- **AI 搜索品牌的 4 类问题**：内容缺失 / 信息失真 / 不可抓取 / 错误关联
- **Schema 标记**：JSON-LD 格式的结构化数据，FAQ/HowTo/Product 是 GEO 三大基础类型
- **语义锚点词库**：把品牌核心概念向量化，对应到用户提问语义空间
- **内容主权**：品牌主动获取 "模型引用资格" 的过程——避免信息缺失或失真
- **多模态内容**：文本 + 图像 + 音频 + 视频，AI 引擎对多模态内容的引用率更高
- **E-E-A-T 原则**：Experience（经验）、Expertise（专业）、Authoritativeness（权威）、Trustworthiness（可信）——内容平台质量审核标准

## Mental Models
- **"被看见" vs "优先被看见"**：前者只要求 AI 收录，后者要求 AI 引用且放在前位
- **内容工程 vs 单篇内容**：GEO 是系统工程，单篇爆款没用，要矩阵化、体系化
- **"用户语言" 替代 "品牌语言"**：把技术性描述转为用户易理解的描述，是 GEO 的核心动作

## Anti-patterns
- **"内容缺失" 不处理**：AI 查询品牌无企业信息时直接错失曝光机会
- **"信息失真" 不更新**：旧版本内容/过期数据在 AI 回答中误导用户
- **不重视 Schema 标记**：缺乏结构化设计，AI 无法有效抽取关键信息
- **错误关联不澄清**：AI 将竞品信息归于本品牌，造成品牌认知混乱
- **内容不针对平台偏好**：同一份内容在所有平台平铺，效率最低

## Key Takeaways
1. GEO 是系统性内容工程，不是单篇内容优化
2. 内容四工程必须并行：信息纠偏 + 结构化 + 抓取打通 + 语义增强
3. 内容搭建要从 "用户身份×使用场景×AI 搜索意图" 三维出发
4. 三大平台（豆包/文心/元宝）的引用偏好差异巨大，需针对性布局
5. Schema 标记（FAQ/HowTo/Product）= GEO 内容的"快捷通道"
6. "用户语言" 替代 "品牌语言" 是 GEO 内容转化的核心动作
